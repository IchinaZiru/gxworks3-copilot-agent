# GX Works3 自然言語操作AIエージェント — PoC設計・実装仕様書

版数: v0.1（ドラフト） / 作成日: 2026-11-19 / 社内承認前

## 1. エグゼクティブサマリー

GX Works3の操作は、初心者にとって独自の画面構成やラダー編集手順の習得が必要である。本PoCでは、GitHub CopilotのComputer Useを使い、利用者が自然言語で指示した基本操作をGX Works3上で代行できるか検証する。

第1段階は「画面認識 → 新規プロジェクト作成 → 保存」を完了条件とし、続いてマニュアル参照とAgent Skillsを導入する。ラダープログラム編集は追加の検証対象とする。

| 区分 | 今回の方針 |
| --- | --- |
| 目標 | 自然言語によるGUI操作の成立と再現性の確認 |
| 方式 | ローカルCopilot harness + Computer Use + 操作マニュアル |
| 初期スコープ | 画面読取、プロジェクト新規作成、保存、結果報告 |
| 拡張スコープ | 簡易ラダー作成、Skill化、比較評価 |
| 対象外 | PLC実機書き込み、設備運転、稼働設備の設定変更 |
| 開発原則 | RAG・独自MCPは先行導入せず、実測で必要性を判断 |

> **判断ポイント** Computer Useが「使える」ことは、GX Works3のラダー編集領域まで正確に操作できる保証ではありません。画面操作・ロジック正確性・オフライン検証を別の成功条件にします。

## 2. 背景・目的・期待効果

### 2.1 背景と課題（現時点の仮説）

- GX Works3は豊富な機能を備える一方、初心者がメニュー構成・入力操作・プロジェクト概念を習得する負担がある。
- 経験者の暗黙知に依存する操作を自然言語化し、初期学習の障壁を下げたい。
- 社員から、Copilotにマニュアルを参照させて一部GUI操作を実行できたという情報が共有されている。ただし、実証済み操作の範囲は未確認。

### 2.2 目的

新入社員等がGX Works3の全操作を事前に暗記しなくても、安全なテスト環境で、意図を自然言語で伝えて基本作業を進められる体験を検証する。

### 2.3 期待効果・評価方法

| 期待効果 | 確認方法 |
| --- | --- |
| 操作習得の負担軽減 | 初学者の操作達成率・完了までの支援回数を比較 |
| 作業時間の短縮 | 同一タスクの人手操作時間とAI実行時間を記録 |
| 操作知識の再利用 | 別セッションで同じ操作が再現できるか検証 |
| 手順の可視化 | マニュアル参照元と操作ログを残す |

## 3. スコープと前提条件

### 3.1 対象範囲

| 優先 | 対象作業 | 成功状態 |
| --- | --- | --- |
| P0 | GX Works3画面の読み取り | 主要メニューや状態を誤認なく報告 |
| P0 | 新規プロジェクト作成 | 指定CPU・言語の空プロジェクトが開く |
| P0 | 保存・再オープン | 指定先に保存され、再読込で内容一致 |
| P1 | マニュアル参照 | 指定文書の対象手順を説明してから操作 |
| P1 | 操作手順のSkill化 | 別チャットで同一操作を再現 |
| P1 | 1接点・1コイルのラダー編集 | 回路構成が意図どおりに表示される |
| P2 | オフライン変換・シミュレーション | 対応CPUで変換結果・動作を確認 |

### 3.2 対象外

- PLC実機への接続・書き込み・運転・停止操作。
- 実設備に紐づく制御パラメータの変更や本番プロジェクトの上書き。
- 完全自律の無人運転、および安全性に関わる制御設計の自動承認。
- GX Works3本体のソースコード改修。

### 3.3 実施前提・未確認事項

- 社内PCはWindowsでGX Works3が動作することを前提とする。OS・GX Works3の版数・対象CPUは初日に確認する。
- GitHub Copilotの契約・権限、VS Codeの版数、組織のComputer Use利用ポリシーを確認する。
- 参照するGX Works3マニュアルは社内利用許可のあるものに限り、モデルへの送信範囲を確認する。

## 4. システム構成・動作フロー

### 4.1 論理アーキテクチャ

```text
ユーザー（日本語の指示）
  ↓
GitHub Copilot（ローカル Copilot harness / モデル）
  ├─ .github/copilot-instructions.md : 共通方針・安全制約
  ├─ docs/*.md                    : 操作マニュアル
  ├─ .github/skills/*/SKILL.md    : 検証済み手順の再利用
  └─ Computer Use                : 画面確認・クリック・入力
  ↓
GX Works3（オフラインのテストプロジェクト）
  ↓
画面状態の再確認・結果報告・評価ログ
```

### 4.2 主要シーケンス

- 利用者が「何を作成するか」とCPU・言語・保存先を指定する。
- Copilotが対応マニュアルを参照し、操作前に計画と不確実な点を提示する。
- Computer UseでGX Works3の画面を認識し、必要なクリック・入力を行う。
- 画面遷移や保存結果を都度確認し、違いがあれば停止する。
- 実証できた内容と未確認事項を分けて報告し、結果を記録する。

### 4.3 モデルとharnessの区別

モデルは推論を担当し、harnessはツール実行・許可・セッション管理を担当する。VS CodeのComputer Useは、Windows/macOSのローカルCopilot harnessでの利用が公式に案内されている。モデルを変更しただけでComputer Useの利用条件が変わるわけではない。

## 5. 機能要件

| ID | 機能 | 要件・受入基準 |
| --- | --- | --- |
| FR-01 | 画面認識 | 現在のGX Works3ウィンドウと開いているダイアログを特定し、表示に基づく状態を報告する。 |
| FR-02 | 操作計画 | 操作前に対象CPU・言語・保存先を確認し、不足があれば作業を停止する。 |
| FR-03 | 新規作成 | マニュアルに従い新規プロジェクトを作成し、指定条件を人間が確認できる。 |
| FR-04 | 保存 | 既存ファイルを無断で上書きせず、指定先へ保存した事実を確認する。 |
| FR-05 | マニュアル参照 | 参照したファイルと該当節／ページを結果報告に記録する。 |
| FR-06 | 状態検証 | 各重要操作後に画面状態を確認し、期待画面と異なる場合は停止する。 |
| FR-07 | ラダー作成 | オフラインでX0接点→Y0コイルの1段回路をGUI編集できる。 |
| FR-08 | Skill再利用 | 検証済み操作をSkill化し、新しいセッションで実行できる。 |
| FR-09 | ログ出力 | 指示、操作結果、手動介入、所要時間、失敗理由を残す。 |
| FR-10 | 例外処理 | 予期しない画面・権限拒否・操作不明時に無理に続行しない。 |

## 6. 非機能要件・安全設計

| 項目 | 要求 |
| --- | --- |
| 安全性 | 実機ネットワーク・PLC接続を物理／ネットワーク設定で分離する。安全設定はプロンプトだけに依存しない。 |
| アクセス権 | 最小権限で検証し、必要な範囲のみアプリ操作を許可する。 |
| 機密保持 | 画面内の社内機密・顧客情報・認証情報を露出させない。AIへの送信条件は組織規程に従う。 |
| 再現性 | 初期画面・CPU機種・ソフト版数・マニュアル版数を記録する。 |
| 可監査性 | Copilotの出力だけで成功判定せず、GUIの状態と生成物を人間が確認する。 |
| 失敗時復旧 | 別名で保存し、テスト用ファイルから開始して、失敗後は初期状態に戻す。 |
| 可用性 | 実験環境で使えない機能は代替案検討に回し、ツール制限を回避しようとしない。 |

> **安全上の境界** AIへの指示ファイルは必ずしも厳格な権限制御ではありません。PLCネットワーク分離、テストプロジェクト分離、OS権限、利用者承認、操作ログといった外側の対策が必要です。

## 7. 開発環境・ファイル構成

### 7.1 必要な構成

- Windows上のGX Works3（版数と対象CPUは初日に確認）。
- VS Code（Computer Useに対応する版）と有効なGitHub Copilotアカウント。
- Computer Useに関するVS Code設定とローカルCopilot harness。
- 操作に必要な範囲へ絞ったGX Works3マニュアル。

### 7.2 ワークスペース案

```text
gxworks3-ai-agent/
├─ .github/
│  ├─ copilot-instructions.md
│  └─ skills/
│     ├─ gxworks3-basic/SKILL.md       (基本操作成功後)
│     └─ gxworks3-ladder/SKILL.md      (ラダー操作成功後)
├─ docs/
│  ├─ project-creation.md
│  ├─ project-save.md
│  └─ ladder-edit.md
├─ evaluation/
│  └─ results.csv
├─ HANDOFF.md
└─ README.md
```

このフォルダはCopilotの指示と評価用であり、GX Works3が保存するPLCプロジェクトとは分離する。

### 7.3 Computer Useの初期設定（確認済みの公式手順）

- VS Code設定「chat.agentHost.computerUse.enabled」をONにして再起動する。
- 新しいローカルCopilot harnessセッションを開始する。
- チャットに「/computer on」を入力し、必要な許可を確認する。
- 対象がGX Works3であることを確認してから読み取り専用の操作テストを行う。
- 作業終了時は必要に応じて「/computer off」で無効にする。

## 8. Agent Skills・RAGの位置付け

| 技術 | 位置付け | 導入時期 |
| --- | --- | --- |
| copilot-instructions | 常時適用したい基本方針・制約・参照ルール | 最初から |
| docs/*.md | タスクごとの操作根拠・手順・注意点 | 画面認識後 |
| Skill Creator（外部） | 成功した操作を再利用可能なSkillに変換する支援 | 手順の実証後 |
| gxworks3-basic（自作） | 作成・保存の検証済み手順 | PoC成立後 |
| gxworks3-ladder（自作） | GUIラダー編集の検証済み手順 | ラダー実証後 |
| awesome-copilot | ドキュメント生成などの外部Skillを探すカタログ | 必要時のみ |
| RAG | 大量の公式／社内マニュアルを検索する場合の追加構成 | 初期は不要 |
| 独自MCP・UI Automation | 標準Computer Useで不安定な操作の補完 | 必要性実証後 |

Agent Skillは「操作を教える再利用手順」であり、GUI操作エンジン自体ではない。公開Skillのスクリプトや依存関係は導入前にレビューする。Skill Creatorに含まれるClaude専用の評価処理などは、Copilot環境での利用を個別に確認する。

## 9. 実装工程とゲート

| 工程 | 主な作業 | 完了条件 |
| --- | --- | --- |
| P1 事前確認 | 利用権限・OS・GX Works3版数・対象CPU・実機分離 | 承認・条件記録 |
| P2 基本環境 | Copilot harness／Computer Use有効化 | 画面読み取り成功 |
| P3 操作PoC | 新規作成、保存、再オープン | 生成物を人間が確認 |
| P4 文書参照 | 操作マニュアル整理、ファイル指定参照 | 根拠ファイルと操作の一致 |
| P5 Skill化 | Skill Creator等で成功手順を保存 | 新規チャットで再実行 |
| P6 ラダーPoC | 1接点・1コイル回路、必要なら変換 | 画面の回路内容が一致 |
| P7 評価 | 3条件比較・ログ集計・改善点整理 | 成功率と失敗理由を報告 |

> **初日の推奨ゴール** P1〜P3（画面認識、新規作成、保存）の達成。余力があればP4に着手し、P5以降は安全・再現性を確認しながら段階的に進めます。

## 10. 検証計画・判定基準

### 10.1 テストケース

| ID | 試験項目 | 合格条件 |
| --- | --- | --- |
| TC-01 | 画面認識のみ | 主要メニュー／表示状態が実画面と一致し、操作しない |
| TC-02 | 新規プロジェクト | 指定CPUとラダー言語のテストプロジェクト作成 |
| TC-03 | 保存と再読込 | 指定先から開き直して内容が一致 |
| TC-04 | マニュアルあり再実行 | 参照元・操作手順を提示して同操作を完了 |
| TC-05 | 別セッション再現 | Skillありで同条件・同一タスクを実施 |
| TC-06 | ラダー編集 | X0接点／Y0コイルの1段を正確に編集 |
| TC-07 | 異常画面 | 未想定ダイアログで停止・人間へ確認 |

### 10.2 比較条件と指標

同じ初期状態で条件A「Computer Useのみ」、条件B「+ マニュアル」、条件C「+ 検証済みSkill」を比較する。予備評価では各条件3回程度から開始し、結論の一般化には追加試行を要する。

- 操作成功率＝成功回数／試行回数。成功は画面表示だけでなく生成物確認を含む。
- 所要時間＝指示開始から検証完了まで。手動介入待ち時間も別途記録。
- 人間の介入回数＝途中停止からの再指示、手動操作、設定修正。
- 失敗分類＝認識失敗／クリック失敗／手順誤り／設定不整合／権限制限／その他。

### 10.3 Go / No-Go基準

- 基本操作が成功し、オフライン環境かつ保存確認が取れた場合にSkill化へ進む。
- 原因不明のダイアログ、意図しない画面操作、対象外操作が生じた場合は一旦中断し原因を記録する。
- ラダー編集の成否と制御ロジックの妥当性は別に判定する。

## 12. 社内PCへの持ち込み・社員への共有

本書は外部環境で作成したドラフトのため、ファイルの社内取り込み可否を事前に確認する。承認済みの文書管理・通信経路を利用する。公開サイトや「リンクを知っていれば閲覧できる」共有先には、非公開の仕様や社内情報を置かない。

| 推奨順位 | 共有方法 | 想定条件 |
| --- | --- | --- |
| 1 | 社内SharePoint / Teams / OneDrive | 担当者が許可された文書ライブラリへアップロードし、社内限定リンクを共有。 |
| 2 | 会社承認済みGitリポジトリ | リポジトリ権限がある場合にMarkdown/PDF等を追加し、社内PCで取得。 |
| 3 | 承認済みメール添付・ファイル転送 | 組織ポリシー上で外部からの取り込みが許可されている場合のみ。 |
| 避ける | 公開Gist・公開GitHub・無制限の個人クラウド | 組織内部の設計内容を公開する経路としては使用しない。 |

外部から社内PCへのファイル転送が不可の場合は、社内PC上のCopilotに本書の概要を入力して、社内の承認済み保管場所で再生成する。ChatGPTの一時ファイルリンクは、社内PC向けの恒久的な公開配布URLではない。
